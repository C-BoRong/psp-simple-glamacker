# 移植流程：先验证技术，再填充剧情

「开始」先介绍这两个阶段，并确认由谁测试。未选择时等待用户回答；同一作品已经选过则沿用。随后运行 `doctor.ps1`、核对 Git，按 `project/PORT-PLAN.md` 接续。模板示例能构建仅证明环境可用，不等于目标作品通过技术验证。

**用户手动测试**：agent 可按任务检查环境、构建 ISO，并注明构建自带的静态镜像检查。交付 ISO、简短操作路线和预期结果；不另跑测试套件、不启动或操控模拟器、不截图，也不代做真机验收，除非用户另行指定。收到反馈前记「待用户手测」，收到后注明设备、版本和反馈来源。

**agent 自动测试**：在当前作品和可用环境内运行相关测试，报告实际执行的路线、结果和未覆盖项。缺模拟器或真机时如实标为未测。用户中途改选手测时停止自动操作，保留已有结果。下文所有验证步骤均服从已选分工。

**每项任务的进度回报**：说明本次完成内容和验收状态，再用两行收尾，同步到进度表。当前阶段写「阶段名 · 所在步骤 · 状态」；剩余流程按顺序列出当前阶段的未完成项、之后的阶段，以及眼下需要谁做什么。模板维护与目标作品移植分开写；没有剩余事项就写「无」。例如：

> 当前阶段：技术验证 · 分支与读档样本已构建，待用户手测。
>
> 剩余流程：用户测试两条分支并读回存档 → 修复反馈、评审样本 → 按章填充 → 全路线与最终 ISO 验收。

## 一、技术验证：证明这个作品能移植

1. 确认版本、语言、授权输入、必保内容与选择的首段。将解包资源原样放入 `inputs/original/`。先全量**盘点**章节、分支、资源类型与指令频次，但此时只转换代表性片段。每种高风险机制至少留一个原作定位（文件、标签、指令或时间码）。
2. 选一条能穿过完整运行链的短路线：进入游戏、对白及语音、一个真实选项、一次转场、存档退出再读回、鉴赏入口。开场没覆盖的视频、特殊字形、复杂演出、最长对白、最重资源要另取样。记录原作的预期画面、选择结果和时间。
3. **先选 UI 方向，再调颜色。** 向用户展示模板 XMB 预览，询问「沿用这种半透明 XMB，还是复刻目标游戏？」可按页面混用。提醒可提供原游戏菜单、鉴赏、存读档等示例图，最好有选中、未解锁、空槽、覆盖确认状态；截图可放在 `inputs/original/ui-reference/`。没有图则列出已有证据及未确认部分，不妨碍技术盘点。选复刻意味着为该作品适配布局和控件，不是自动换肤；按 `docs/UI-STYLE.md` 做一页对照，经用户认可再铺开。PSP 外壳图标与游戏内部 UI 分开选择。
4. 为样本建立只读转换和可重现的 Windows 构建，逐个验证输入、存读档一致性、音画时序与失效处理。记录 ISO 体积和全量外推、峰值内存、换场/读盘停顿及帧时间；明确工具、测试路线和设备。原作素材未知命令不得跳过。
5. **阶段评审**：给用户一个可运行的样本 ISO、可对照的画面、能力清单（通过／失败／未测）、阻塞项及预算。核心机制不通或估算超限时，先修正或商定缩小范围。真机不可用可经用户明确同意带风险进入填充，但不能写成硬件通过。将用户对样本、UI 和下一阶段范围的决定写入计划。

## 二、剧情填充：证明每条路线都接完整

1. 按章节或路线拆批，维护源脚本 → 节点 → 资源 → 结局映射。分别统计总量、已转换、已播放验证、失败、经用户同意排除；扫描到的文件不能算作已验收。
2. 每批复用第一阶段的格式和共享素材，核对缺图、语音对应、分支目标、文字分页、时间轴、解锁和存档恢复。重跑代表路线，并从上一章的存档跨入新章。记录本批 ISO 增量、性能异常与修复提交。
3. 新指令、新状态或新媒体类型进入「待验证」队列：保留源位置，提取最小重现，局部返回第一阶段。无依赖的章节可以继续；不得伪造空处理来宣称全量完成。
4. **交付评审**：从干净输入重建最终 ISO，检查所有必需资源内置、≤1,500,000,000 字节。对照入口、全部已约定结局、跨章读档和鉴赏内容；分别报告主机校验、PPSSPP、各真机型号和没做的测试。记录构建命令、提交、镜像哈希及剩余限制。
